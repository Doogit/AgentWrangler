# AgentWrangler 0.2.0

AgentWrangler is a local dashboard for Claude Code token spend. 0.2.0 is a large release: most of the dashboard
was redesigned, the number of detectors went from 9 to 31, recommendations became one ranked list with measured
effects, and a new **Rate my setup** page grades your Claude Code setup. Usage limits are now read through your
own Claude Code CLI, so AgentWrangler no longer uses your Claude login to call Anthropic. One-click apply is off
in this release.

Short version: [CHANGELOG.md](https://github.com/Doogit/AgentWrangler/blob/main/CHANGELOG.md). Upgrade notes are at the end of this page.

## Performance

- **Usable sooner on first launch.** The newest sessions are read first, so the dashboard opens before your full
  history is loaded. The rest loads in the background, and a status bar at the bottom shows how far it has got.
- **Stays responsive while it works.** Reading transcripts is split into short time slices. History,
  recommendations, Usage patterns and headroom are built in a background worker and served from snapshots, so a
  page request does not wait on them.
- **Less re-reading.** Copied or renamed transcript files are recognized and not read again. Warm restarts skip
  files that have not changed.
- **Less polling.** One browser tab polls the daemon for status and shares it with your other tabs. Pages refetch
  only the data that changed.
- **A responsive daemon.** Measured in our release test gate while a backfill is running: daemon event-loop p99
  ≤ 50 ms, and each of the 67 budgeted API routes within its p95 latency budget (250 ms for most routes).
- **Windows:** child processes no longer flash a console window.

## UI / dashboard

- **New navigation.** The sidebar is grouped into Observe (Overview, Workspaces, Sessions), Analyze (Rate my setup,
  Usage patterns, Recommendations) and Configure (Settings), with links to Help and the Glossary.
- **Overview redesign.** A Usage limits card, a spend card with $ and Tokens tabs, a 12-week chart of your implied
  weekly limit, your most expensive sessions of the last 7 days, and the top recommendations.
- **Sessions.** A paged list with filters and Load more, and columns for cache hit %, peak context and subagent
  cost. The session detail page shows the cost breakdown, friction, the evidence behind each signal, and an
  "Investigate" prompt you can copy into Claude Code.
- **Workspaces.** A time window control (default: all history) and a High-cost model use column (share of turns on
  Opus, Fable or Mythos). Sessions run from a git worktree inside a repo now count toward that repo's workspace.
- **Usage patterns** (new page): groups avoidable spend and reliability problems by root cause, ranked, with the
  affected sessions and a link to the fix where one exists.
- **Help** (new page): the full in-app guide. The same text is in [docs/help/guide.md](https://github.com/Doogit/AgentWrangler/blob/main/docs/help/guide.md).
- **Settings** is grouped into Essentials, In-session guards, Integrations and Advanced.
- A loading screen on first start, and loading placeholders for each page section.
- **Removed:** the Briefs tab (`#/briefs` now opens Rate my setup), the work-records controls, and the Overview
  cache-efficiency tile.

## Detectors

- **31 detectors, up from 9.** New ones cover oversized tool and task output, cache misses and cache breaks, tool
  error rates, edits before reads and failed edits, repeated errors, edit flip-flops, shell failure clusters,
  permission denials, MCP output size, subagent over-spawning, interrupted turns, slow orientation before the first
  edit, mechanical work on the main thread, expensive failed sessions and destructive operations.
- **Tested both ways.** Every detector has a fixture that must fire and a near miss that must not.
- Dollar figures on cards are estimates at list prices, not measured savings. A card says **Not estimated** when it
  cannot price the finding.
- The limit-burn forecast now uses your pace over the last 24 hours.
- Many accuracy fixes: shared turns are no longer counted twice, sidechain and subagent turns are attributed and
  priced, and good interrupts are no longer counted as waste.

## Handlers and recommendations

- **One ranked list.** Recommendations are ordered by the dollars per week each card shows.
- **Cards explain themselves.** Each card has a short summary, why it matters, the evidence (sessions and turns),
  and its actions: Install hook, Copy snippet, Copy prompt, and Open in Claude Code (see Off in 0.2.0).
- **Measured effects.** Press **Track** and then **I completed the change**. AgentWrangler compares the 14 days
  after the change with the baseline and records the result in the Impact ledger. A change it cannot measure says
  "Effect not measured" instead of guessing.
- **Undo.** You can reopen a dismissed recommendation and undo an adoption.
- History is folded and grouped; filters for type, basis and last seen; small findings sit in their own
  below-the-floor section.
- Resetting recommendations keeps the ones you acted on and their measured effects.
- Pricing uses each turn's own model tier.

## Judge module (Rate my setup)

- **Rate my setup** grades your Claude Code setup (settings, hooks, CLAUDE.md and memory files, MCP servers,
  permissions, skills and agents) against a list of checks, and shows a tier, what each check found, and the next
  steps to reach the next tier. A snapshot is saved each time your grade changes, so you can see what changed.
- **Judge me** (optional) asks Claude for a written review of your setup. It shows you the exact payload, and what
  Claude Code itself adds (such as your account email and OS version), and asks for consent first. It runs your
  own `claude` CLI in an isolated mode (no tools, no MCP servers, no session saved). Secrets are blocked and names are scrubbed from what is sent. Typical cost: $0.30–$0.40 of your
  Claude usage.

## Usage limits

- **Read through your own Claude Code.** By default AgentWrangler runs your own `claude -p /usage` in the
  background, only while the dashboard is open: at most every 5 minutes when you have been active, hourly when
  idle, and not at all while the statusline reading is fresh. Your `claude` CLI makes the call; AgentWrangler never
  reads your Claude login for it. Only percentages, reset times and model labels are kept.
- **Statusline as the alternative.** Settings > Install statusline makes `agentwrangler statusline` your Claude
  Code statusline (wrapping the one you had). It updates the card on every turn with no background calls.
  The newer of the two readings wins; per-model weekly rows come only from `/usage`.
- **Off switch.** Settings > Usage limits from Claude Code, or `AW_USAGE_CLI=off`. The Overview shows a one-time
  notice that the background reader is on.
- The card keeps the last good reading across restarts and marks it stale when it is old.
- **Changed from 0.1.0:** AgentWrangler no longer sends your Claude Code login token to Anthropic's usage endpoint.

## Ingest and data

- New data read from transcripts: `/clear` and `/compact` commands, session titles, compaction boundaries, which
  subagent or workflow agent ran each turn, and links from `git commit` calls to the commits they made.
- A better tool-error classifier, with a one-time repair of stored rows.
- Price fixes: Opus 5.5 and Sonnet 5.5 cache reads, Haiku 5.5 tiers, and a re-price of stored history.
  Prices are checked for freshness.
- **Safer database handling.** 38 new database migrations. Only one daemon runs per database. A database written by a newer AgentWrangler is
  refused instead of being damaged. Before migrating, the database is backed up next to itself (`.pre-migrate.bak`,
  skipped above 512 MB). The daemon prints a warning at start if the database sits in a OneDrive-synced folder.
- **GitHub outcomes sync** shows its status, can test the connection and retry, and pages through pull requests.
- **Removed API routes:** `/api/work-records*`, `/api/offload-share`, `/api/self-churn`, `/api/trends/cache-write`
  and `/api/overview/flavor`.
- The local database can now hold secrets-filtered command text and error excerpts so cards can show real
  evidence. This content stays on your machine (see Security and privacy).

## CLI, install and packaging

- **New default address: `http://127.0.0.1:2929`** (was `127.0.0.1:47821`). Set `AW_PORT=47821` to keep the old
  one. Update bookmarks.
- `agentwrangler statusline [--wrap "<your old command>"]` is the command Claude Code runs as its statusline;
  install it from Settings. Install keeps a timestamped backup of `settings.json`; uninstall puts your previous
  command back.
- `agentwrangler audit` (experimental) copies your database, writes an evidence pack and a prompt, and you run the
  printed `claude` command to get a findings report. It never starts or talks to the daemon. See
  [Getting started](https://github.com/Doogit/AgentWrangler/blob/main/docs/getting-started.md).
- The npm package now includes this changelog.
- Still requires Node.js 22 to 24.

## macOS

- The Claude Code Keychain entry is read in the background with a 3-second limit and cached, so it never blocks the
  dashboard. It is used only to show whether you are signed in and your plan tier.
- **Open in Claude Code** opens Terminal.app. AgentWrangler checks that the launch worked and gives up after 20
  seconds.
- Ending a Claude Code session from the dashboard (after you confirm) stops that session and its child processes,
  never the AgentWrangler daemon.
- Path comparisons work with macOS's symlinked temp folders.
- A macOS first-run smoke test now runs in CI, next to the existing macOS tests and npm-tarball install.

## Security and privacy

- **Your Anthropic API key is never passed to a `claude` that AgentWrangler starts** (Judge me, Open in Claude Code,
  `/usage`). Those use your Claude subscription login. The daemon reads `ANTHROPIC_API_KEY` only for the optional
  bytes-to-token calibration.
- AgentWrangler no longer sends your Claude Code login token anywhere.
- Every write request to the daemon needs a per-run token, and the daemon still listens on 127.0.0.1 only.
- **Guardrail hooks no longer skip your permission prompt.** The context-budget, loop and limit-burn hooks used to
  answer "allow" along with their warning, which skipped Claude Code's permission prompt for that tool call. They now
  only add the warning, in the place Claude Code reads it.
- **Privacy boundary, restated.** Inside the app, the local database and UI may store and show transcript content
  (secrets-filtered) where it makes a recommendation useful. Nothing is synced, backed up to a cloud or sent as
  telemetry. Transcript and pull-request content is kept out of the published code and package by automated checks.
  Details: [docs/privacy.md](https://github.com/Doogit/AgentWrangler/blob/main/docs/privacy.md).

## Off in 0.2.0 / known limits

- **One-click apply is off.** The apply endpoints return `403 APPLY_DISABLED`. Use **Copy prompt**, or turn on
  Settings > Advanced > Experimental actions to get **Open in Claude Code**, which opens your own `claude` in a
  terminal. AgentWrangler does not change files for you.
- **Not yet tested on a real Mac:** the Keychain "allow access" prompt and the Terminal Automation permission prompt
  that macOS may show the first time. macOS CI covers install and first run.
- **Open in Claude Code** uses Terminal.app on macOS; other terminal apps are not supported yet.
- **The usage reader needs a recent Claude Code** on your `PATH` that supports `/usage`. If it is missing, too old,
  or slow, the card says why and you can switch to the statusline.
- `agentwrangler audit` is experimental; its output format may change.

## Upgrade notes

1. The dashboard moves to `http://127.0.0.1:2929`. Set `AW_PORT=47821` to keep the old address.
2. Your database is migrated on first start, after a backup (see Ingest and data). On a large database the first
   start can take a minute or two.
3. The usage card fills itself from `claude -p /usage`. To use the statusline instead, install it from Settings.
4. Apply jobs from 0.1.0 can no longer be confirmed. Installed hooks can still be removed from Settings.
5. If you installed the guardrail hooks in 0.1.0, reinstall them from Settings. Installed hooks point at the
   package's own hook files, so with `npx` they can keep running the 0.1.0 copies and miss the permission-prompt fix.
